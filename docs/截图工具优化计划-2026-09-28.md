# 截图工具优化计划（2026-09-28 立项，下一阶段主战场）

> 用户结论：v1.2.0 截图相关工具"还有很多问题，但能用"。本文汇总三轮验收积累的全部截图侧问题与规格落差，按优先级排列，作为截图专项的实施依据。规格口径见《参考图规格拆解》A 组。

## P0 稳定性（先立后破）

1. **截图管线后台线程碰 UI**（CaptureController.swift:132-211，P1-12）：Task 默认全局执行器，失败分支直接建 Toast/NSPanel；疑似造成一次进程崩溃自重启（wave-2 观测 pid 变化，待查 ~/Library/Logs/DiagnosticReports 的 crash log 定罪）。→ 整链路 MainActor 化。
2. **⌘⇧A 呼出不稳定**：系统弹窗/钥匙串框抢焦点时覆盖层闪现即逝（wave-2 实测）。→ 覆盖层置顶策略 + 激活时序加固，参考 hideOverlaysForCapture 之后的链路。
3. **Esc/↵ 兜底依赖辅助功能权限**（CaptureController.swift:280-289）：未授权时静默失效，用户感知"时灵时不灵"。→ 权限检测 + 明确提示；或换 Carbon 局部方案。

## P1 规格建设（对标参考图 A1/A2）

4. **选区 8 个白色手柄**：参考图规格 A1，当前只有 1.5pt 绿框、完全未实现——选后无法微调，误触零容错。
5. **工具栏吸附选区下方**（A2）：当前是编辑器卡片内底部条；且 ShotActionBar（截图后工具条）的按钮仍是 SwiftUI Button——**未激活态会失灵（nonKeyTap 未覆盖此文件），与本轮面板修复同款问题，专项第一刀**。
6. **W×H 尺寸标签**：代码已有（黑底胶囊），实机未验证显示与 Retina 换算。
7. **遮罩明暗跳变**（CaptureController.swift:428-444）：悬停窗口与空白切换时全屏明暗闪烁，规格要求"选区外恒定压暗 + 窗口提亮"。
8. **全屏 App 无法智能选窗**（:182-186）：≈整屏窗过滤把全屏应用一并排除。
